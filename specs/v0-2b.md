# Cards v0.2b — Synthesis & Summaries

**Version:** v0.2b  
**Depends on:** v0.2a (collections + scoped chat recommended)  
**Theme:** Produce research artifacts on ingest and via structured modes, not just free-form chat.

## Problem

Adding a paper to the library only indexes text. The user still has to read (or chat) to learn what the paper contributes. Free-form chat does not match common research tasks: comparing methods, drafting lit review sections, or extracting structured fields.

## Goals

1. **Ingest summaries** — auto-generate and store a structured summary when a paper is added.
2. **Structured research modes** — preset workflows that return formatted, citable outputs.
3. **Library cards show value immediately** — TL;DR visible before opening Chat.

## Non-goals (v0.2b)

- Hybrid retrieval / reranking (v0.2c)
- Export to BibTeX/CSV (defer to v0.3)
- User notes/highlights
- Background job queue (sync generation on ingest is acceptable for v0.2b)

---

## User stories

| ID | Story |
|----|-------|
| B1 | When I add a paper, I see a 3-line TL;DR and key contributions on the Library card within ~30s. |
| B2 | I run **Compare** on 2–5 papers and get a table: methods, datasets, findings, limitations. |
| B3 | I run **Lit review outline** on a collection and get themes, agreements, contradictions, gaps. |
| B4 | I run **Methods extraction** on one paper and get structured fields with citations. |
| B5 | Summary generation fails gracefully (paper still indexed; card shows "Summary unavailable"). |

## Data model

### PaperSummary (new)

Stored alongside library metadata. **Recommendation:** Chroma paper-level metadata document OR SQLite `paper_summaries` table keyed by `paper_id`.

```ts
type PaperSummary = {
  paperId: string;
  status: "pending" | "ready" | "error";
  tldr: string;                    // ≤ 3 sentences
  keyContributions: string[];      // bullet list
  methods?: string;                // paragraph or null for non-empirical
  limitations: string[];
  generatedAt: string;
  model: string;                   // e.g. llama-3.1-8b-instant
};
```

### Research mode request

```ts
type ResearchMode =
  | "compare"
  | "lit_review"
  | "methods"
  | "free";                       // existing chat

type ModeRequest = {
  mode: ResearchMode;
  message?: string;               // optional focus question
  paperIds?: string[];
  collectionId?: string;
};
```

### Mode output shapes

**Compare** — markdown table + optional narrative:

| Paper | Methods | Dataset / n | Key finding | Limitations |
|-------|---------|-------------|-------------|-------------|

**Lit review** — markdown sections:
- Overview
- Theme 1, 2, …
- Points of agreement
- Contradictions
- Gaps & future work

**Methods** — structured JSON rendered as card:
- Study design, population, intervention, outcomes, statistical approach
- Each field has `text` + `citationIndexes[]`

## API changes

### Ingest pipeline

After successful Chroma indexing (`rag/app/routers/ingest.py`):

1. Trigger summary generation (sync in v0.2b).
2. Call Groq with paper title, abstract, and first N chunks (or abstract-only if `abstract_only`).
3. Parse JSON response into `PaperSummary`; store in SQLite or Chroma metadata.

New optional RAG endpoint:

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/library/{paper_id}/summary` | Return `PaperSummary` |
| POST | `/library/{paper_id}/summary/regenerate` | Force re-generate |

Alternatively, keep summary logic entirely in Next.js API calling Groq + SQLite.

### Chat / modes API

Extend `POST /api/chat` or add `POST /api/research`:

- `mode` param selects system prompt template.
- All modes use scoped retrieval (from v0.2a) then mode-specific prompt.
- Response format:
  - `compare` / `lit_review`: stream markdown tokens (same SSE as chat)
  - `methods`: stream JSON or markdown; client renders structured card
- Citations included in all modes (evidence panel from v0.2a applies).

### Prompt templates (sketch)

Store in `web/lib/prompts/`:

- `summary.ts` — ingest-time structured JSON output
- `compare.ts` — requires ≥2 papers; instruct model to fill table rows per paper
- `lit-review.ts` — synthesize across chunks with mandatory `[n]` citations
- `methods.ts` — single-paper; extract only from context

All prompts: **answer only from context**; say insufficient evidence when needed.

## UI changes

### Library (`library-paper-card.tsx`)

- Expandable summary section below title:
  - TL;DR (always visible when ready)
  - "Show more" → contributions, methods, limitations
  - Skeleton while `status === "pending"`
  - Badge: "Summary unavailable" on error

### Chat page

- **Mode selector** tabs or dropdown above input:
  - Ask (free) | Compare | Lit review | Methods
- Compare/Lit review require ≥2 papers in scope (or active collection with ≥2).
- Methods requires exactly 1 paper in scope (or prompt user to narrow).
- Mode-specific placeholder text and empty-state hints.
- Compare output: render markdown tables with `remark-gfm` or similar.
- Methods output: structured field cards with clickable citations.

### Ingest UX (`search-page-client.tsx`)

- After add: toast "Indexing… summary generating" if async; or spinner on card until summary ready.

## Acceptance criteria

- [ ] Newly ingested paper shows TL;DR on Library card after ingest completes.
- [ ] `abstract_only` papers still get a summary from abstract text (no methods section).
- [ ] Compare mode with 3 scoped papers returns a table with one row per paper and ≥1 citation per row.
- [ ] Lit review mode on a 5-paper collection returns themed sections with citations.
- [ ] Methods mode on single paper returns ≥3 structured fields with citations.
- [ ] Ingest succeeds even if summary generation fails.
- [ ] Evidence panel (v0.2a) works for citations in mode outputs.

---

## Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Groq rate limits on bulk ingest | Queue summaries; show pending state; retry with backoff |
| JSON parse failures from LLM | Use `response_format: json_object` where supported; fallback regex extract |
| Compare table hallucination | Require citation per cell; post-validate empty cells |
| Long ingest time | Return ingest response immediately; generate summary async in v0.2b.1 if needed |
