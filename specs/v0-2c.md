# Cards v0.2c — Retrieval Quality

**Version:** v0.2c  
**Depends on:** v0.1 minimum; benefits from v0.2a scoping and v0.2b summaries  
**Theme:** Fix the crude RAG pipeline so answers pull from the right passages across the right papers.

## Problem

Current pipeline limitations (v0.1):

- **Chunking:** `chunk_text()` splits at fixed 512 characters with overlap — breaks mid-sentence, ignores document structure.
- **Retrieval:** single embedding query, top-k by cosine distance, no reranking, no diversity.
- **Chat:** single-turn only — `POST /api/chat` sends one `message`, no conversation history.
- **PDF parsing:** page-level text exists in `pdf_parser.py` but abstract ingest uses character chunks without section labels.

## Goals

1. **Section-aware chunking** — chunks respect paragraphs/sections; metadata includes `section` label where possible.
2. **Hybrid retrieval** — combine vector search with keyword scoring (BM25 or lightweight TF-IDF).
3. **Reranking** — retrieve top 20 candidates, rerank to final top 5.
4. **Multi-turn chat** — send conversation history (or rolling summary) to Groq.
5. **Retrieval diversity (MMR)** — broad questions return chunks from multiple papers, not one PDF.

## Non-goals (v0.2c)

- New embedding model / GPU inference
- Full re-ingest UI (provide one-time `reindex` script/endpoint)
- Agentic multi-step reasoning

## User stories

| ID | Story |
|----|-------|
| C1 | Questions about "methods" retrieve chunks from methods sections, not random paragraphs. |
| C2 | Keyword-heavy queries (gene names, dataset names) find relevant papers via hybrid search. |
| C3 | Follow-up "what about the second paper?" uses prior turn context. |
| C4 | "Compare findings across my library" retrieves at least one chunk per paper when library has ≤5 scoped papers. |
| C5 | I can re-index the library after upgrading chunking without re-searching sources. |

## Technical design

### 1. Section-aware chunking

**File:** `rag/app/services/chunking.py`

Replace character-only splitting with:

1. Split text into paragraphs (`\n\n`).
2. Merge paragraphs up to `chunk_size` tokens/chars without splitting sentences.
3. Detect section headers via regex/heuristics:
   - `^(Abstract|Introduction|Methods?|Results?|Discussion|Conclusion|References)\b`
   - Numbered headings `^\d+\.`
4. Attach metadata: `section: str | null`, `page: int | null`.

**PDF path:** `pdf_parser.py` already chunks per page — add section detection across concatenated page text or use PyMuPDF block structure (`page.get_text("dict")`) for better boundaries.

**Chroma metadata** (add fields):

```python
{
  "section": "methods",      # new
  "paper_id": "...",
  "chunk_index": 0,
  "page": 3,
  ...
}
```

### 2. Hybrid retrieval

**File:** `rag/app/routers/retrieve.py`

Pipeline:

```
query
  → embed_query(query)           # existing
  → chroma.query(n_results=20)   # vector candidates
  → bm25_score(query, candidates) # keyword scores on chunk text
  → fuse_scores = α * vector + (1-α) * bm25   # α default 0.7
  → optional: filter by paper_ids (v0.2a)
  → rerank top 20 → top 5
  → optional: MMR for diversity
```

**BM25 implementation options (pick one):**

- `rank_bm25` in Python over in-memory candidate set (simplest; no new infra)
- Chroma native full-text if available in pinned version (evaluate)

**Config** (`rag/app/config.py`):

```python
retrieval_top_n: int = 20      # initial fetch
retrieval_top_k: int = 5       # final return
hybrid_alpha: float = 0.7
mmr_lambda: float = 0.5        # 0 = max diversity, 1 = max relevance
enable_mmr: bool = True
```

### 3. Reranking

**Phase 1 (v0.2c):** LLM-free cross-encoder optional — use **score fusion only** (vector + BM25).

**Phase 2 (optional):** `sentence-transformers/ms-marco-MiniLM-L-6-v2` cross-encoder reranker (CPU, ~80MB, same stack as embeddings).

Rerank on the 20 fused candidates; return top 5 to chat API.

### 4. MMR (Maximal Marginal Relevance)

When `len(paper_ids) > 1` or unscoped library chat:

- After reranking, greedily select chunks that maximize  
  `λ * relevance − (1−λ) * max_similarity_to_already_selected`
- Ensures multi-paper coverage for broad queries.

Skip MMR when scoped to a single paper.

### 5. Multi-turn chat

**File:** `web/app/api/chat/route.ts`

Extend request:

```ts
type ChatMessage = { role: "user" | "assistant"; content: string };

type ChatRequest = {
  message: string;
  history?: ChatMessage[];   // last N turns, max 10
  paperIds?: string[];
  collectionId?: string;
  topK?: number;
};
```

Retrieval uses **latest user message only** (or optional query rewrite in v0.3).

Groq messages:

```ts
[
  { role: "system", content: systemPrompt },
  ...history.slice(-8),
  { role: "user", content: userPromptWithContext },
]
```

**Client:** `chat-page-client.tsx` already keeps `messages[]` — pass last N turns in the POST body.

**Token budget:** truncate history if context exceeds model limit; prioritize recent turns + retrieved chunks.

## Re-indexing

Existing chunks use old schema. Provide:

| Method | Route | Description |
|--------|-------|-------------|
| POST | `/reindex` | Re-fetch and re-chunk all papers in library (admin) |

**v0.2c scope:** CLI script `rag/scripts/reindex.py` that reads library paper list, re-fetches content, replaces Chroma entries. UI button optional.

Papers need stored `source`, `external_id`, `pdf_url` in metadata (already present) to re-fetch.

## Acceptance criteria

- [ ] Chunks from PDF ingest include `page` and `section` when detectable (manual spot-check on 3 papers).
- [ ] Query containing a rare proper noun (e.g. dataset name) ranks relevant chunk higher than vector-only baseline.
- [ ] Unscoped query over 5-paper library returns chunks from ≥3 distinct papers (MMR on).
- [ ] Follow-up question referencing "the previous answer" works with 2+ turn history.
- [ ] Reindex script successfully replaces chunks without duplicate `paper_id` entries.
- [ ] Retrieval latency p95 < 2s on library of ~50 papers / ~500 chunks (CPU, local).
- [ ] No regression when `history` is omitted (single-turn behavior unchanged).

## Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Re-chunking invalidates old vectors | Version metadata `chunk_schema: 2`; reindex script |
| BM25 + vector score scale mismatch | Normalize scores to [0,1] before fusion |
| Multi-turn blows context window | Cap history turns; truncate retrieved chunks |
| Section detection false positives | Default `section: null`; don't over-trust labels |
