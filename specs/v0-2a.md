# Cards v0.2a — Trust & Scope

**Version:** v0.2a  
**Depends on:** v0.1  
**Theme:** Make RAG answers verifiable and limit chat to a meaningful subset of the library.

## Problem

v0.1 chat retrieves top-k chunks from the entire library and shows citation badges with no source text. Users cannot verify claims or work on a single paper/topic. `retrieve.py` already supports `paper_ids` filtering, but the UI and chat API do not expose it.

## Goals

1. **Evidence panel** — click a citation to see the exact retrieved chunk, paper metadata, and relevance score.
2. **Scoped chat** — restrict retrieval to one paper, a multi-select set, or a named collection.
3. **Collections** — group papers by project/topic and use them as the default chat scope.

## Non-goals (v0.2a)

- Auto-summaries on ingest (v0.2b)
- Structured compare/lit-review modes (v0.2b)
- Retrieval quality improvements (v0.2c)
- User accounts, cloud deploy, export

## User stories

| ID | Story |
|----|-------|
| A1 | As a researcher, I click citation `[2]` and see the exact passage the model used. |
| A2 | As a researcher, I open Chat from a Library paper and ask questions scoped to that paper only. |
| A3 | As a researcher, I multi-select papers in Library and chat across just those papers. |
| A4 | As a researcher, I create a collection (e.g. "Thesis ch. 2") and add/remove papers to it. |
| A5 | As a researcher, I set an active collection in Chat so all questions are scoped to it until I change it. |

## Data model

### Collection (new)

Stored in a lightweight local persistence layer. **Recommendation:** SQLite file mounted as a Docker volume (`cards_data`), accessed from the Next.js API routes (or a thin FastAPI module if preferred).

```ts
type Collection = {
  id: string;           // uuid
  name: string;
  description?: string;
  createdAt: string;    // ISO
  updatedAt: string;
};

type CollectionMembership = {
  collectionId: string;
  paperId: string;      // e.g. "arxiv:2401.12345"
};
```

### Chat request (extend)

```ts
type ChatRequest = {
  message: string;
  topK?: number;
  paperIds?: string[];      // explicit scope; overrides collectionId
  collectionId?: string;    // resolve to paperIds server-side
};
```

### Citation (extend)

```ts
type Citation = {
  index: number;
  paperId: string;
  title: string;
  source: string;
  page?: number;
  chunkId: string;          // NEW — links to evidence panel
  chunkText: string;        // NEW — full retrieved passage
  score: number;            // NEW — retrieval score
};
```

## API changes

### Next.js — Collections CRUD

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/api/collections` | List collections with paper counts |
| POST | `/api/collections` | Create `{ name, description? }` |
| GET | `/api/collections/[id]` | Collection + `paperIds` |
| PATCH | `/api/collections/[id]` | Update name/description |
| DELETE | `/api/collections/[id]` | Delete collection (not papers) |
| POST | `/api/collections/[id]/papers` | Add `{ paperId }` |
| DELETE | `/api/collections/[id]/papers?paperId=` | Remove paper from collection |

### Next.js — Chat (`/api/chat`)

- Accept `paperIds` or `collectionId`.
- Resolve `collectionId` → `paperIds` before calling `retrieveChunks`.
- Pass `paperIds` to `retrieveChunks(query, topK, paperIds)` (already supported in `rag-client.ts`).
- Include `chunkId`, `chunkText`, and `score` in each citation sent via SSE `citations` event.

### RAG service

No required changes for basic scoping — `POST /retrieve` already accepts `paper_ids`.

Optional: `GET /library/{paper_id}/chunks` to fetch a single chunk by id for deep-linking (can defer; chunk text can ship in citation payload).

## Acceptance criteria

- [ ] Clicking a citation opens the evidence panel with the exact chunk text used in the prompt.
- [ ] Chat scoped to one paper does not retrieve chunks from other papers (verify via panel / logging).
- [ ] User can create a collection, add 3 papers, and chat scoped to that collection only.
- [ ] "Chat with selected" from Library pre-fills scope with selected `paperIds`.
- [ ] Scope indicator is visible during chat; user can change scope without losing message history (UI-only history is fine).
- [ ] Empty scope (collection with 0 papers) shows a clear error, not a silent Groq hallucination.
- [ ] No regression to v0.1 unscoped chat when no scope is set (defaults to all library).

---

## Implementation notes

- When `paperIds` is empty after resolution, return 400 before calling Groq.
- Cap `paperIds` length (e.g. 50) to avoid huge Chroma `$in` filters.
- Citation `chunkText` may be long; panel scrolls internally. Do not duplicate full text inline in the chat bubble.
- Collections are local-only in v0.2a; design schema so cloud sync can be added later.
